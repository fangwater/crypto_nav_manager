# FR 建仓成本分析

实现：NAV `/nav/#/fr-entry-cost/:slug` 页面与受账户权限保护的 `/api/analysis/{slug}/fr-entry-cost`。沿用现有 HashRouter，网关入口为 `/nav/`，不新增 Nginx 路由。读取实际成交，以 FIFO 识别当前剩余仓位成本，并按 1 分钟归因；两腿跨分钟时平均参考值。

## 主指标

对线性、同币数的现货多头 / 永续空头，令 Q 为配对后的 base 数量，S/F 为各腿实际成交价格，B_ref 为建仓期间的参考期现价差：

    实际成交基差 B_fill = F - S
    建仓执行成本 = Q × (B_ref - B_fill) + 两腿实际手续费
    成本 bps = 建仓执行成本 / 配对现货成交名义本金 × 10,000

反向套利使用相反的价差符号。返佣作为负手续费；缺失手续费折算不能当作零。跨分片以金额汇总，再用同一名义本金归一化，不直接平均 bps。

初始基差是持仓的经济属性，不直接等于损失。相对零基差的入场价格差可以另列，但不能叫即时亏损或保证收益。完整正套闭环的价差收益是 Q × (B_entry - B_exit)，再加实际 funding、扣除手续费和借贷利息。本页聚焦建仓，不改变 NAV 的收益计算。

## FIFO 与分钟归因

先从策略历史起点（或用户选定的期初快照）重放两腿各自的数量 FIFO，平仓消耗最老的同腿库存。再对剩余现货与反向合约库存按最老优先配对。支持部分成交、部分平仓、方向反转以及合约腿先成交。

这是一种库存成本配对约定，不声称恢复了订单因果关联。保留成交 ID、两腿成交时间、配对数量和跨分钟跨度。账户和币种之间不混配；绝不使用相同 USDT 名义金额替代相同 base 数量。

每个配对片段使用两腿成交所在分钟及中间分钟的参考值平均，再按片段名义本金汇总。分钟边界不清空 FIFO。交易实际数量不足时保留残余敞口；不能因为策略目标中性，就通过平均价格或强制缩放数量制造中性。

期初快照只有持仓与估值价时，原始建仓价未知。其数量参与平仓和匹配，成本必须保留未知状态，不能把快照估值价当作真实建仓价。展示窗口之前的成交也必须参加 FIFO 重放。

## 数据与估算限制

首选参考是同一时刻、同一交易标的的现货与永续 BBO 中间价之差。分钟 OHLC 的独立收盘价不保证同步，不能直接当作精确盘口基差。

Premium index 是交易所的溢价指标，不等于实际可交易期现基差。使用它时，参考价差采用 S × premium，主指标必须标为“建仓成本估算 / 相对 premium 的偏离”，不能称为纯滑点。对跨分钟的配对使用涵盖分钟的均值；缺少任意所需分钟则该片段参考成本未知，并显示覆盖率。不可跨缺口前向填充或用另一个交易所替补。

分钟结果是事后归因，可能使用成交之后才完成的分钟数据，不适合作为历史决策时刻已知的信号。精确拆分报价损耗、对冲等待及市场冲击还需要决策时间、同步 BBO 和订单关联。

## 页面与验收

- FR 账户、币种、持仓截至时间；显示主成本金额和 bps、实际成交基差、手续费、参考覆盖率。
- 分钟归因和 FIFO 明细；明确当前剩余仓位与期间全部成交的区别。
- 分别显示可配对数量、残余数量、跨分钟占比和时间跨度；缺失数据不输出虚假的完整总成本。
- 复用 NAV 会话与账户授权；读取实际成交，不触发交易或改变现有收益账。
- 验证部分成交/平仓、先合约后现货、反套、跨分钟、历史预热、缺失参考/手续费/期初成本，以及金额和数量守恒。
- 前端类型检查、Oxlint、相关验证脚本和生产构建；Rust 格式与针对性测试；按仓库要求部署并验证授权 API、页面与静态资源。

## 运行方式

页面从账户详情或首页“FR 建仓成本”进入。可选择币种、持仓截至时间，以及可选的参考基差情景（bps）；留空时自动读取本交易所分钟 premium。自动参考目前支持 Binance、Bybit、Gate；Bitget 未验证公开 premium 历史端点，保留未知参考，手动情景明确标识，不伪装成市场数据。

FIFO 重放完整账户起点至截止时间；分钟建仓图只包含仍未平掉的库存。最近 24 小时净数量图用于观察临时错位，最后一分钟只计算截至所选时间已入库的成交。原始成交数量沿用 NAV 的交易所数量规范化；未纳入历史成交的划转、借币利息等可导致成交重建与实时资产数量不同。

公开数据按需补齐，优先复用原有 Binance/Bybit 数据库分钟表；额外缓存只在进程内，不修改原有收益账或增加采集 worker。每次最多补齐 32 页 / 40 秒，刷新继续；未收盘分钟不纳入自动参考。成本覆盖率反映成交价格、费用和完整所需参考是否齐全，缺失一部分则完整总成本未知。

## 手续费、成交结构与基差变化

按用户指定，不推断目标仓位是否已经建满，直接使用**当前 FIFO 剩余库存最后一笔配对完成时点**，即已配对片段两腿较晚成交时间的最大值。更晚的未配对单腿成交不会推迟这个时点，之后的平仓也不改写剩余库存原始成交时间。

手续费与 maker/taker 结构提供两个明确范围：

- 当前 FIFO 配对库存：与主成本卡片一致，费用按剩余数量分摊。每条腿按其成交金额计算 maker/taker/unknown 占比，未知角色保留在分母。同一成交拆成多个配对片段时，成交笔数按 ID 去重，金额和费用按片段加总。
- 建仓区间全部成交：从当前配对库存最早的已知成交到最后配对时点，包含区间内的平仓、减仓和再平衡。不得把这个成交总费用当作当前剩余库存分摊费用。

实际价差展示现货 VWAP、合约 VWAP、F − S 绝对价差（USDT / base）和相对现货 VWAP 的 bps；方向调整后的参考偏离单独标为有利/不利/与参考一致/未知。Premium 参考不足以识别纯滑点。

基差变化包含三个时点和三段差值，统一采用未调整套利方向的 premium bps：

1. 开始：当前配对库存最早成交所在分钟。
2. 最后配对：当前剩余库存最后一个片段的较晚成交所在分钟。
3. 查询截至：截至查询时间已经完整结束的最后一分钟，不拿更晚的分钟冒充当时已知值。

差值分别为最后配对减开始、截至减最后配对、截至减开始。起点或终点缺失则该差值未知；中间缺口在图上断线并报告覆盖数量，不插值。图保留 1 分钟原始频率，不把缺口连成连续曲线。长区间优先补齐以上时点，再补中间历史。恒定的手动参考只用于情景分析，其市场基差变化值保持未知，避免把人工恒定假设解释为“市场没有变化”。

含未知成本的期初库存时不能恢复原始建仓起点；区间统计和开始基差保持未知。配对之后的基差变化属于持仓阶段，不重复算入建仓执行损耗。

## 按币种筛选与排序

页面只追踪当前持有的 FR 仓位。每次刷新先读取策略实时 pre_trade_exposure 快照，以合约腿数量非零确定当前币种；已平仓的合约、现货残余和 FIFO 历史残余不会使币种继续出现。不再提供历史币种范围或历史截至时间切换。币种下拉框、汇总与参考补齐队列使用同一份当前持仓列表；点击币种进入明细，保留本次刷新固定的成交截止时间，并切回市场参考。

阈值留空为不限，支持任一腿 taker 成交额占比、不利执行偏差 bps、入场基差绝对值 bps、手续费 bps、成本估算 bps 的 `>=` 筛选，可选择满足任一或全部指标；搜索币种和最低配对本金始终作为额外约束。表头支持升降序，未知值无论排序方向都放在末尾。不设置自动异常评分或策略风险结论。

两腿分别展示 maker/taker/unknown 成交额占比。原始基差为 `(F − S) / S × 10000`，保留正负，并另提供绝对值排序；正套/反套在币种下方展示，大基差本身不代表损失。执行偏差沿用按套利方向调整的相对 premium 估算，正值才是不利偏差。手续费与成本同时展示 bps 和 USDT，不把返佣或有利执行取绝对值。

未知不是零，也不是未触发阈值。未知条件按三值逻辑合并；可选择保留无法判断的币种，并明确计数。成交角色未知时，已知 taker 占比只构成下界：已达到阈值可判定满足，已知 taker 加全部未知角色仍达不到可判定不满足，其余保留未知。无配对库存的成本与比例展示为未知。

受同一账户授权保护的 `/api/analysis/{slug}/fr-entry-cost-overview?endMs=...` 只重放当前持有币种的完整历史成交，逐币种返回精简汇总；全账户重放串行执行以限制内存和数据库压力。初次汇总只读取已有分钟参考，不为所有币种同时请求交易所。页面只在首次打开、切换账户或用户点击“计算 / 刷新”时加载一次；不定时刷新、不自动启动参考补齐。用户点击“手动补齐参考”才串行调用原明细端点的 `summaryOnly=true` 模式，执行一轮补齐，固定同一截止时间，逐行更新，可停止；不会自动开启下一轮。汇总补齐每币种最多 8 页 / 8 秒，按配对本金与所需分钟的比例优先覆盖有效配对区间，以整页复用附近配对分钟，避免从历史起点扫描大段无关持有期。单币明细仍按 32 页 / 40 秒补齐完整基差轨迹。单币市场参考明细也会更新对应汇总行；手动参考情景不混入币种比较。未验证自动参考的交易所保留未知。

筛选核验：`node frontend/scripts/verify_fr_cost_screen.mjs`，覆盖任一/全部、正负基差、边界值、返佣、成交角色缺失和未知值的升降序。

当前持仓必须来自 90 秒内的实时快照（最多容许 5 秒时钟前偏），使用 entry 自身的 ts_ms，而不是数据库入库时间。快照读取失败、过期或缺少两腿数量时返回 503，界面提示暂不可用，不用过期快照或 FIFO 重建结果冒充当前持仓；有效空快照才显示无持仓。保留仍有合约仓位但缺少历史成交或价格的币种，成本显示未知，不以金额缺失或 base 数量微小推断已经平仓。原始 FIFO、手续费和收益账不变。

## 可计算片段与可视化

完整成本仍保持严格口径：任意必要价格、分钟参考或费用缺失，整仓指标仍为 null。另提供 covered.fee / deviation / cost：分别仅汇总该指标完整可计算的配对片段，bps 分母使用这些片段的现货本金，数量覆盖率使用片段 base 数量除以整组配对数量。不同指标覆盖范围可能不同，不得直接相加，不外推成整仓成本，不将未知当零。手续费为 BNB 等第三资产且缺少历史 USDT 折算时，仍保留未知，不用现在价格或默认费率伪造实际费用。

表格、排序和筛选先使用完整指标，否则使用明确标注覆盖率的可计算部分。主成本卡与执行偏离说明使用相同展示口径。成本图用浅色表示部分覆盖，各指标分组展示而不堆叠；散点图横轴为两腿最大 taker 比例，纵轴为入场基差绝对值，点大小随配对本金变化，颜色表示相对参考的执行偏差方向或未知。图表随筛选联动，可悬停查看范围并点击币种进入 FIFO 明细。顶部单独报告可计算成本、参考缺口及费用折算缺口数量。

页面提供“数量覆盖是什么意思？”说明：例如 100 个配对币中有 80 个币的数据完整，则覆盖率为 80%；金额与 bps 只对应这 80 个币，bps 用它们的成交本金作分母。该比例衡量数据完整度；手续费、执行偏差和总成本所需数据不同，覆盖率可不同。
